Works where paste does not

A full set of events for each character, so the page reacts as it does to a real keyboard.

Real event order

Each character fires keydown, beforeinput, input, and keyup in order, with a random delay of 20 to 80 ms by default.

Controlled inputs

Uses native value setters, so React, Vue, and Angular state picks up each key press.

Any editable field

Works in inputs, text areas, and contenteditable regions.

Your typing speed

Pick Slow, Normal, or Fast, or set your own minimum and maximum delay.

Progress and stop

A badge on the toolbar icon counts characters. Trigger it again while it types to stop.

Finishes cleanly

A final change event lets validation and submit buttons react. An empty clipboard or a field you cannot edit does not break the page.

Questions

Why doesn't Ctrl+P work as the shortcut?

Chrome reserves Ctrl+P for printing, so extensions can't claim it. The default is Ctrl+Shift+V or Cmd+Shift+V, and you can set your own at chrome://extensions/shortcuts.

Does it work with React and Vue forms?

Yes. It writes through the browser's native value setter before it dispatches the input event, so controlled components detect the change as they do with real typing.

What happens if the field goes read-only mid-paste?

Typing stops at once and logs a warning to the console. Nothing is retried or force-inserted after a field is disabled or made read-only.

Does the extension ever see my clipboard content elsewhere?

No. It reads the clipboard only at the moment you trigger a paste, and it uses the text only to type into the field you targeted. The text is never sent anywhere.
